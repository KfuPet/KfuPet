# KfuPet 角色包制作指南

面向为 KfuPet 制作角色（模型）的创作者。本文档说明角色包的目录结构、配置文件字段，以及部位图如何挂到骨骼上。

- 参与**代码开发**请看 [CONTRIBUTING.md](../CONTRIBUTING.md)
- **骨骼清单**（有哪些骨骼、叫什么）见 [skeleton/SKELETON_BONES.md](skeleton/SKELETON_BONES.md)
- **骨骼接口**（开发者工具用的命名管道 API）见 [skeleton/SKELETON_API.md](skeleton/SKELETON_API.md)

---

## 一、角色包放在哪里

在 `Characters/` 下建一个文件夹，一个子文件夹就是一个角色包，文件夹名即角色名：

```text
Characters/
└── 你的角色名/
    ├── character.json     角色信息（必需，缺这个包会被判为无效）
    ├── attachments.json   部位图与骨骼的绑定关系
    ├── reactions.json     触摸反应配置：事件提示与备用台词
    ├── images/            部位图
    ├── prompt.md          角色提示词
    ├── preview.png        列表卡片用的预览图
    └── logo.png           列表卡片用的作者头像
```

程序查找 `Characters` 的顺序：先看程序所在目录，找不到就向上回溯最多 6 层到项目根。开发时放进项目根目录的 `Characters/` 即可。

> ⚠️ 当前版本**同时只加载一个角色**：附件取「第一个含 `attachments.json` 的包」，提示词取「第一个含 `prompt.md` 的包」。多角色切换尚未实现，所以调试时建议只保留一个角色包。

## 二、character.json

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 角色包唯一标识（英文/数字） |
| `name` | string | 角色名称，显示在列表卡片上 |
| `version` | string | 版本号，如 `1.0.0` |
| `author` | string | 作者名称 |
| `authorAvatar` | string | 作者头像路径，相对角色包目录 |
| `description` | string | 角色描述 |
| `preview` | string | 预览图路径，相对角色包目录 |
| `tags` | string[] | 标签，供图库搜索过滤 |
| `prompt` | string | 提示词文件路径。**当前版本固定读取 `prompt.md`，该字段尚未生效** |

```json
{
  "id": "baiyy",
  "name": "白摇摇",
  "version": "1.0.0",
  "author": "咲",
  "authorAvatar": "logo.png",
  "description": "活泼开朗的二次元宅女……",
  "preview": "preview.png",
  "tags": ["二次元", "元气"],
  "prompt": "prompt.md"
}
```

## 三、部位图（images/）

- 必须是 **带透明通道的 PNG**，背景透明
- 各部位图建议从**同一张原画布按 1:1 裁切**，不要单独缩放 —— 整套图共用 `attachments.json` 里的一个 `scale`
- 文件名建议与骨骼 ID 对应，但**文件名不强制**；真正决定挂到哪根骨骼的是 `attachments.json` 里的 `boneId`

## 四、attachments.json

### 根字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `version` | string | 配置版本号 |
| `scale` | number | 整套部位图的统一缩放系数 |
| `attachments` | array | 附件列表 |

### 每条附件

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 附件唯一标识，同一包内不可重复 |
| `boneId` | string | 挂到哪根骨骼，取值见[骨骼清单](skeleton/SKELETON_BONES.md) |
| `name` | string | 显示名称，工具里辨认用 |
| `resource` | string | 图片路径。相对角色包目录，也支持绝对路径 |
| `pivot` | `[x, y]` | 旋转锚点，取值为 0~1 的**图片自身比例** |
| `offset` | `[x, y]` | 相对骨骼锚点的偏移（DIP） |
| `zOrder` | int | 渲染层级，值越大越靠前 |
| `visible` | bool | 是否显示 |

### scale 怎么定

窗口画布是 **480 × 600 DIP**，角色的目标高度是 **410 DIP**（头顶在画布中心上方 230，脚底在中心下方 180）。

```text
scale = 410 / 原画布里人物的像素高度
```

例：白摇摇的原画布 1536×2048，人物实际高度 1913px，则 `scale = 410 / 1913 ≈ 0.21432`。

### pivot 怎么定

`pivot` 是**关节**在图片自身里的位置。摆姿势时部位会绕这个点旋转，所以要设在与父骨骼连接的那一端：

| 部位 | pivot | 含义 |
|------|-------|------|
| 头部 | `[0.5, 1.0]` | 底边中点（下巴 / 颈） |
| 身体 | `[0.5, 0.0]` | 顶边中点（颈根） |
| 上臂 / 小臂 | `[0, 0.5]` 或 `[1, 0.5]` | 袖口或手肘那一端的中点 |
| 大腿 / 小腿 | `[0.5, 0.0]` | 顶边中点（髋 / 膝） |

### 图片最终落在哪

程序按下式计算图片左上角：

```text
图片左上角 = 骨骼位置 + offset − (图宽 × scale × pivot.x, 图高 × scale × pivot.y)
```

想让某个部位对齐，就调它的 `offset`。窗口与骨骼统一使用 DIP，配置与屏幕缩放无关；图片由渲染层做高质量降采样。

## 五、reactions.json（触摸反应配置）

角色被**双击**某个部位时，或被**按住头部快速左右来回滑动**（抚摸）时，会有一段反应：**优先由 AI 现场生成一句符合人设的回应**；未接入 AI（没有启用中的模型）或 AI 请求失败时，改用**备用台词**；两者都没有时，触摸不会有任何反应。

文件有 `eventPrompt`、`reactions` 两段配置，都可以省略：

```json
{
  "version": "1.0.0",
  "eventPrompt": {
    "headPet": "主人按住你的头，轻轻来回抚摸了几下",
    "head": "主人戳了戳你的头",
    "armLeft": "主人戳了戳你的右手",
    "armRight": "主人戳了戳你的左手",
    "legLeft": "主人戳了戳你的右腿",
    "legRight": "主人戳了戳你的左腿",
    "body": "主人戳了戳你的身体",
    "instruction": "请用符合你人设的一句话回应，只输出这一句话（30 字以内），不要引号、不要旁白、不要解释。"
  },
  "reactions": {
    "head": ["唔哇～头发要被揉乱啦！", "嘿嘿……摸头要提前打招呼哦！"],
    "armLeft": ["呀！右手被捏到了～"],
    "armRight": ["呀！左手被抓住了～"],
    "legLeft": ["呀，右腿痒痒的～"],
    "legRight": ["痒痒的！左腿不许戳啦～"],
    "body": ["喂喂，戳肚子会痒的啦！"]
  }
}
```

### eventPrompt：发给 AI 的事件提示（可选）

AI 收到的用户消息形如 `（触摸事件）主人戳了戳你的右手。请用符合你人设的一句话回应…`，"发生了什么"与"应答要求"都在这里改：

| 键 | 含义 |
|----|------|
| `headPet` | 抚摸头部（按住头部来回滑动） |
| `head` / `armLeft` / `armRight` / `legLeft` / `legRight` / `body` | 双击对应部位 |
| `instruction` | 尾部应答要求，整套共用 |

- **缺省项用程序内置的默认文案**（上例即内置默认），整段不写也能工作

### reactions：备用台词（可选）

AI 不可用时用的台词，按部位随机抽一条：

| 部位键 | 对应骨骼 | 触发方式 |
|--------|----------|----------|
| `head` | `head` | 双击，或按住头部快速左右来回滑动（左一下 + 右一下） |
| `armLeft` / `armRight` | `arm_left_*` / `arm_right_*` | 双击 |
| `legLeft` / `legRight` | `leg_left_*` / `leg_right_*` | 双击 |
| `body` | `body` | 双击 |

说明：

- **左右指画面上的左右**（事件键、部位键都一样），与骨骼命名一致（见下一节）；图片文件名按角色自身视角命名，正好相反，别写混了
- **两段里的正文都按角色自身视角写**：画面左侧的手脚其实是角色的右手/右腿，所以 `armLeft` 写「右手」；上例即按此写法
- 备用台词**只在 AI 不可用时**生效（没有内置兜底）：整个文件没提供、或某个部位没写，该部位在 AI 不可用时不会有反应，建议六个部位都写全
- 每个部位可以写多条台词，同一部位不会连续说同一句
- 触发一次后冷却 **2 秒**，冷却期间的触摸动作一律无效
- 头部只响应抚摸与双击，**不参与拖动窗口**；移动窗口请按住身体、手臂或腿

## 六、⚠️ 左右方向是反的

这是最容易踩的坑：

- 骨架里的 `arm_left_*` / `leg_left_*` 指的是**画面左侧**（x 为负）
- 而美术做图时习惯按**角色自身的左右**命名 —— 正面视角下，角色的左手出现在画面右侧

两者正好镜像，所以图片与骨骼是**交叉绑定**的：

| 图片 | 绑到骨骼 |
|------|----------|
| `arm_left_upper.png`（实际是画面右侧那条手臂） | `arm_right_upper` |
| `arm_right_upper.png` | `arm_left_upper` |
| `leg_left_upper.png` | `leg_right_upper` |
| `leg_right_upper.png` | `leg_left_upper` |

判断方法：看这张图在原画布里落在左半边还是右半边 —— 落在**右半边**的图，绑到骨架里名字带 `right` 的骨骼。

## 七、完整示例

[Characters/白摇摇/attachments.json](../Characters/白摇摇/attachments.json) 是一份可直接参考的真实配置，片段如下：

```json
{
  "version": "1.0.0",
  "scale": 0.21432,
  "attachments": [
    {
      "id": "body",
      "boneId": "body",
      "name": "身体",
      "resource": "images/body.png",
      "pivot": [0.5, 0.0],
      "offset": [0.0, -15.24],
      "zOrder": 20,
      "visible": true
    },
    {
      "id": "leg_left_upper",
      "boneId": "leg_right_upper",
      "name": "右大腿",
      "resource": "images/leg_left_upper.png",
      "pivot": [0.5, 0.0],
      "offset": [-20.6, -69.21],
      "zOrder": 10,
      "visible": true
    }
  ]
}
```

`zOrder` 的建议顺序（从后往前）：双腿 `10~13` → 身体 `20` → 手臂 `31~34` → 头部 `40`。腿要在身体之前，这样裙摆能盖住大腿根部；手臂在身体之后，袖口才能压住肩部。

## 八、调试与验证

- 程序启动时自动读取并挂载附件；**关闭程序时会把当前附件状态回写**到 `attachments.json`
- 骨骼调试线框默认关闭，可在设置里打开，用来对照骨骼与图片的位置
- ⚠️ 在 KfuPet-Tool 里「上传图片」会把图存到程序目录下的临时缓存（退出即清理），所以正式素材请放进 `images/` 并在 `attachments.json` 里引用
